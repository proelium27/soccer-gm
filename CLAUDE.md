# soccer-gm

A client-side, BBGM-style soccer management sim (TypeScript, React, Vite, IndexedDB). `SOCCER_GM_SPEC.md` is the full design brief and M0-M6 build order; `DESIGN.md`/`PRODUCT.md` and `docs/superpowers/specs/*` hold detailed feature/design docs. All milestones M0-M6 are done and merged (see "Milestone status" below).

> **This file is a condensed ledger, not a changelog.** Blow-by-blow constant-retune history (dated before/after values, dynasty-audit numbers) lives in git history and the `docs/` design specs — don't re-add it here. Keep entries to *what a feature is, where it lives, and its non-obvious gotchas.*

## Commands

```bash
npm run dev        # Vite dev server
npm run build      # production build
npm test           # vitest run (full suite)
npm run test:watch # vitest watch
npm run typecheck  # tsc --noEmit
npm run cli        # scripts/cli.ts (headless sim harness for audits)
```

Audit scripts live in `scripts/` (e.g. `divisionAudit.ts`, `weakLeaguesAudit.ts`) — run with `tsx`.

**EA FC roster converter** (`scripts/eafcRosterConvert.ts` + `scripts/eafc/`, docs in `docs/eafc-import.md`): turns an EA FC player CSV into a roster file for the Leagues → Import Custom League flow, for playing with real clubs/players. Dev-only and **never shipped or committed** — the CSV and generated JSON are gitignored, the game keeps shipping fictional clubs (trademark caution). The load-bearing part is the rescale: EA overalls are **rank-matched onto a freshly generated world's OVR distribution** rather than used raw (a generated world spans ~23-81 and only reaches 90+ via progression; EA's top flights run 47-91), so the imported world carries the same OVR distribution a generated one does and the anti-inflation equilibrium is untouched. Per-skill ratings come from EA's attributes (the two sets are both 1-99 and mostly namesakes) then get uniformly shifted to hit the rescaled overall, so players keep their individuality; potential gets its *own* curve (different distribution — reusing the overall curve gave every wonderkid an identical ceiling). **Leagues are matched by `league_id`, never by name**: names collide across federations and the exports drop the country prefix ("Bundesliga" is Germany's *and* Austria's, "Premier League" England's *and* Ukraine's), which silently imported 12 Austrian clubs into the German top flight — `scripts/eafc/inspectLeagues.ts` audits a dataset for exactly this before you trust it. **Coverage is now all 16 competitions** (Belgium and Turkey added 2026-08-12; `COVERED_COMPETITIONS` is derived from the rules so the "which divisions stay fictional" report can't drift). Two traps that generalize: **(a)** FC26 has *three* leagues named exactly "Pro League" — Belgium's (4), Saudi Arabia's (350), the UAE's (2013) — so Belgium has **no bare name rule at all** and is reached by id only; a `pro_league` pattern would have put Al Hilal in the Belgian top flight. **(b)** `normalizeLeague` **must not fold accents**, however much `s_per_lig` ("Süper Lig") looks like a bug: folding was tried and measured to hand Brazil's "Série A" (14 clubs) to Italy and "Primera División" to Spain, since both then match a pattern *and* are unique names in the file, so the unambiguous-name fallback trusts them — 19 foreign clubs, silently. Turkey carries the mangled form as a pattern instead. No dataset seen so far has Belgium's, Turkey's or Portugal's second tier, so those resolve by name only and stay fictional unless a names file fills them. `applyRosterFile` realigns each slot's shuffled `academyBase` (`realignAcademyBases`, 2026-08-10): imported clubs are sorted by `computeTeamRating` and handed *that same group's* existing anchors in descending order, so a superclub can't inherit a weak youth anchor and drift over a long dynasty. **It's a permutation, not a recalculation** — same multiset, reassigned once, nothing derived from the imported ratings — so the anti-inflation equilibrium is untouched (a test pins the multiset). Only squad-*replaced* clubs take part, so a partial import can't degrade untouched clubs; the corollary is an imported club can only take an anchor another imported club held.

**Imported clubs draw no crest art (2026-08-10, user call).** `ClubCrest` keys crest images by **tid — a slot** — which is right for the shipped fictional clubs (a club's name is editable, its tid never changes) and wrong the moment a slot becomes a real club, since the badge then belongs to the club it displaced. `applyRosterFile` flags every slot the file *named* (squads or not — an identity-only entry is exactly the stale-crest case) with `StoredTeam.importedIdentity`, and `CrestArtProvider` suppresses art for those tids. **A context, not a prop**, because `ClubCrest` is rendered from 14 call sites that mostly hold only a tid; one of them forgetting the flag would show a wrong badge on that surface alone — the kind of bug that hides. Wrapped around the in-league shell (`Layout.tsx`) *and* the new-league club picker, so the preview matches the save. Optional field → no migration (absent = not imported). Knock-on: colors become the club's entire identity, so `mergeRosterFiles` now adopts real colors from the names file (the converter hashes them out of the club name — Liverpool came out purple).

**Roster import is creation-only (2026-08-10, user call).** The per-save "Import Teams" button is gone; the entry point is Leagues → **Import Custom League** → `/new-league?roster=1`. Reason: a roster file *replaces squads*, and `applyRosterFile` drops every replaced player who has no recorded stats — on a save in progress that silently deletes real careers, stat lines and the transfer history keyed to those pids. At creation there is nothing to destroy. Three consequences worth knowing: **(a)** `applyRosterFileToNewLeague` (`teams/rosterImport.ts`) is the entry point, and it re-runs `assignAIFormations` + `reconcileScoutingObserved` after the import, because `createLeagueState` derives both from squads the import then throws away (formations picked for deleted players; the user's fog-of-war stamps pruned along with the pids they pointed at, leaving the imported squad permanently unscouted). It is **only** safe on a fresh league — re-stamping scouting resets every observation to season 1, which mid-save hands the user a fully-scouted squad. **(b)** `resolveRosterSlots` now takes a structural `RosterSlotWorld` (`{competitions, teams}`) rather than a `LeagueStore`, so the club picker can resolve a file against `worldTeamSlots()` — the slot layout of a save that doesn't exist yet — and show real club names *before* paying 4s to generate 6000 players. `worldTeamSlots` duplicates `generateWorld`'s tid layout by necessity; `rosterImport.test.ts` pins it against a real generated world so the two can't drift. **(c)** Crest art does **not** follow an import (`ClubCrest` keys images by tid, i.e. by slot), so an imported club wears whatever crest its slot had. Colors do follow.

**Roster import takes several files (2026-08-11).** A world is authored a league at a time (an AI won't emit twelve competitions of squads in one answer), so both pickers — Leagues → Import and the `?roster=1` screen's "Add another file" — are `multiple` and the selected files are folded by `combineRosterFiles` (`teams/rosterFile.ts`) into the single file `applyRosterFileToNewLeague` applies. Competitions are independent, so combining is concatenation in load order; the one ambiguous case, two files claiming the same competition, can't be interleaved (clubs map *positionally* onto slots) so the later file wins outright and the collision is reported. `PendingRoster` therefore hands over `files[]`, and `NewLeague` keeps the loaded `sources` so later picks add to them rather than replace. A file that won't parse is skipped and named on the picker screen; on the Leagues screen it stops the batch instead, because that screen is left behind on the way to the picker and any error it raised would go with it.

The first `npm test` after any `src/core` change rebuilds the cached test worlds (see `test/` below); later runs reuse them. `SOCCER_GM_NO_FIXTURE_CACHE=1 npm test` skips the cache.

## Architecture (where things live)

- `src/core/` — pure sim logic (no UI/DOM). `constants.ts` is the central tuning table. Sub-areas: `players/` (generation, progression, youth, nationalities), `teams/`, `league/`, `ai/` (GM evaluation core), `transfers/`, `finance/`, `lineup/`, `cup/`, `scouting/`, plus top-level `offseason.ts`, `simThrough.ts`, `promotion.ts`, `loans.ts`, `awards.ts`, `godMode.ts`, `competitions.ts`.
- `src/engine/` — match sim (`matchSim.ts`, `attribution.ts`, `matchRating.ts`, its own `constants.ts`).
- `src/db/` — IndexedDB persistence (`leagueDb.ts`, `activeLeague.ts`) and **`migrate.ts`** (backfills every new field for old saves — update it whenever you add a persisted field).
- `src/ui/` — React pages (`pages/`), components, `context/LeagueContext.tsx` (all league-mutating actions, serialized through one promise chain).
- `test/` — vitest. `test/validation/` holds the M1/M4 §8 gate tests.
  - **A world-wide `max` is not a league statistic, and the M3 top-scorer gate learned this the hard way (2026-08-11).** It asserted a Golden-Boot-shaped band (18–36) but measured the max goals over **every player in the world, second divisions included**. Both halves drift for reasons unrelated to scoring realism: a max rises with sample size (12 competitions → 16 raised it on its own), and tier-2 defences are weaker, so the world max was *set by a tier-2 player* and exceeded every top-flight leader that season (43 vs 32, 40 vs 34). It failed at a 36.2 mean while all 40 measured tier-1 Golden Boots sat between 23 and 34 — inside the band, never once above it. Now measures the **mean tier-1 top scorer** (27.7, per-season range 27.0–28.8), which is what the band describes and is invariant to both world size and tier-2 quirks. `scripts/topScorerProbe.ts` prints both side by side. **Widening the ceiling would have been the wrong fix** — it keeps a number that needs re-widening every time a country is added.
- **Test worlds are cached on disk** (`test/helpers/worldCache.ts`, used by `makeLeague`). `createLeagueState` costs ~4.1s for the 240-club/6000-player world, and vitest gives every test file its own worker process, so an in-process memo died at each file boundary and the same world was regenerated in all 36 files that wanted one — the single dominant cost in the suite. Worlds are now generated once ever into `node_modules/.cache/soccer-gm-worlds/<hash>/` and parsed back in ~12ms (~340x). **Always build test worlds with `makeLeague(tid, seed)`, never `createLeagueState` directly** — the one exception is a test that *reuses its rng after generation* (threading it into a later `simThrough`/`simOffseason`), which needs the rng advanced by generation and so must keep generating; those live in `international.test.ts`, `offseason.test.ts`, `simThrough.test.ts`, `transfersRender.test.tsx`, the m3/m4 validation gates and one case in `loans.test.ts`. Gotchas: **(a)** the cache key is a content hash of **all of `src/core`** plus `src/engine/rng.ts` and the Node version — deliberately broad, because generation cannot then depend on anything unhashed. Narrowing it to generation's current import list reintroduces silent staleness; don't. A core edit costs one rebuild (~60s) and is free thereafter. **(b)** It is only sound because generation is deterministic apart from `meta.created` (a wall-clock stamp) — `fixtureFidelity.test.ts` asserts both that and cached-equals-fresh, and is what stops the cache drifting silently. **(c)** `SOCCER_GM_NO_FIXTURE_CACHE=1` bypasses disk entirely if you ever suspect the cache.

## Core invariants & gotchas (durable — read before touching sim code)

- **RNG stream order is load-bearing.** The sim is seeded/deterministic; inserting or removing an `rng` draw shifts every downstream roll (different ratings, names, results). When adding per-player traits or post-hoc attribution, derive them from a *separate* seeded stream (`mulberry32`/`hashInts` off pids/match-intrinsics), never from the shared `rng`. This has caused real bugs (AI deficits, shifted generation) multiple times — see any "RNG-stream-order" mention in git history.
- **OVR scale:** 65 ≈ average starter, 70 ≈ good starter, 75 ≈ a team's best, 80-85 ≈ league-wide elite, 90+ ≈ rare outlier. `OVR_WEIGHTS` (`constants.ts`) drives both generation and progression's `computeOvr`.
- **Anti-inflation (fragile equilibrium — several mechanics exist only to hold it):** youth intake anchors to a fixed-at-generation `academyBase`, never to the club's current roster average (the torn-out anchor caused unbounded ratchet). Potential is a *scout estimate* (`estimatePotential`), never a growth input. Every position's expected lifetime rating arc is ~0/slightly negative. `developmentBias` (persistent per-player trait, deterministic from pid) **must taper to exactly 0 by peak age**, or inflation reopens. `growthDamping` scales down only *positive* deltas as ovr climbs. `YOUTH_BASE_OFFSET` offsets the fact that `generatePlayer` doesn't vary quality by age. Any new mechanic that shifts these must be dynasty-audited (`scripts/`).
- **The user's club is unmanaged by design** in headless audits — no AI free agency/renewals/buys touch it, so it rots and produces *all* extreme worst-case roster/points stats. **Exclude `userTid` from tail metrics** in any audit, or report it separately.
- **Match composites are z-normalized within each competition.** A weak league reads as average in its own matches; cross-league surfaces (the Cup) must pool participants into a *shared* baseline (`simThrough`'s `cupMatchData`) or the weak club gets normalized back up to parity.
- **Composites bucket by SLOT, not natural position (`rollupComposites` takes `SlottedPlayer[]`, `engine/positionFit.ts`, 2026-08-12).** The team's shape comes from its formation, so every group and weight keys off the slot a player occupies; his own `pos` only decides what it *costs* him to be there (`familiarityPenalty`, in raw rating points: `POSITION_ADJACENT_PENALTY` 6 / `POSITION_FOREIGN_PENALTY` 16 / `POSITION_KEEPER_PENALTY` 35, all in `engine/constants.ts`). Before this, groups were built from `p.pos` and the slot was forgotten after selection, so **moving a defender up the pitch made your defense better** (he stayed in the defensive group at full strength and simply left the attacking one) and `control` had the same inverted sign. `MatchPlayer` now carries `slot`; a substitute **inherits the slot of the man he replaces** (via a *copy*, never mutation — `TeamMatchData` objects are shared across every match built from one `leagueMatchData` call, e.g. `season.ts` builds it once for all 380 fixtures, so mutating a slot would leak into unrelated matches). `slotPlayed` tracks the played slot for the box score, which is built from the *original* roster arrays where a sub still carries his bench slot. Attribution weights, `computeMatchRating`, and every "who's the keeper" lookup follow the slot too. **The load-bearing consumer is the substitution logic, not the XI** — measured, starters are 99.2% exact-fit and 0% foreign, but the bench was putting a player in a foreign slot on **37% of all subs** (a striker replacing a tired centre-back was the single most common swap) because `pickReplacement` was exact-pos-or-anyone. It now maximizes `benchValue - familiarityPenalty(slot, pos)`, and `worthSub` gates on the same penalized value; **those two must stay on one number**, or the sim makes swaps it then punishes. Result: foreign subs 37% → 0.2%, and ~19% fewer subs overall (holding a tired starter on beats wrecking the shape). Chase-the-game subs pass `reshape` to `commitSub` so the arriving attacker plays *his own* position (a genuine shape change, one fewer defender) rather than being stranded in a defensive slot. Also closes the documented `pickReplacement` GK gap: an outfielder forced into goal is now penalized instead of silently leaving `keeping` at a neutral 0.5 while counting as an outfielder. Pure function of attributes, **no shared-`rng` draw**, so stream order is untouched — but composite values change, hence results change, hence the `touchStats.test.ts` scoreline hash was rebased. Measured over 20 seeded seasons: champion pts 79.20 → 80.55, and *variance fell* (champion sd 5.24 → 3.77, bottom sd 6.49 → 3.99), since fewer matches are decided by a side dismantling its own shape late. **Dynasty-audited** (`scripts/slotChurnAudit.ts`, 15 seasons × 2 seeds) for the obvious risk — that punishing thin squads sharpens the strong/weak gap into a procession — and it went the *other* way: distinct champions per league 8.0/8.1 → 9.4/9.3, dominant club's title share 33.3%/31.7% → 28.3%/23.3%, champion pts flat (77.9/78.1 → 78.1/77.4), ovr drift still ~0 (anti-inflation intact), D2 ceiling unchanged within noise. Title races got *more* open, because a side can no longer stumble into a lopsided shape that its raw quality doesn't justify.
- **Composite rollup is position-weighted + star-concentrated (`rollupComposites`, `COMPOSITE_STAR_CONCENTRATION`, 2026-07-21).** `attack`/`defense`/`control` no longer flat-average their position group: each is a position-weighted mean (who drives the phase counts most — ST/W for attack, CM/DM for control, CB for defense) *blended toward the group's single best player* by `COMPOSITE_STAR_CONCENTRATION` (0.3), so an elite individual resists being averaged down by weak teammates ("stars carry their phase"; a balanced XI beats a lopsided higher-OVR one). `finishing` (own shot-share weighting) and `keeping` are deliberately left alone. **Pure function of attributes — no shared-`rng` draw**, so RNG stream order is untouched; it only changes composite *values*, hence match results, hence the `touchStats.test.ts` scoreline hash was rebased a second time (intended, not a touch-attribution regression). Dynasty-audit champion churn before raising the concentration (interacts with league z-norm spread).
- **Shot conversion blends team + individual (`SHOOTER_FINISH_WEIGHT`, 2026-07-20, `simMatchDetailed` only).** `resolveShot` takes a `finishAdj` = the finisher's own skill *relative to his team's average* (shooting for shots, heading for corner headers), added to the team finishing composite for `onTargetP`/`saveP` only — **never xG** (xG stays the team-blind "average attacker" baseline, so goals-vs-xG reveals finishing). Centered on the team average, so it *redistributes* a team's goals toward its best finishers without inflating league scoring; a lone elite finisher on a weak side now genuinely stuffs the sheet (the fast composite-only `simMatch`/montecarlo path is untouched → benchmark gates unaffected). Side effect: the season top scorer rises into the mid-30s (m3-top-scorer gate widened 32→36). Rebased the `touchStats.test.ts` scoreline hash once (intended outcome change, not a touch-attribution regression).
- **Determinism boundaries:** cup rounds and decorative touch-attribution (`passes`/`crosses`) each run on their own seeded streams so they can't perturb league match results — league scorelines stay bit-identical to a fixed baseline hash (`touchStats.test.ts`; the baseline was rebased once for the finishing change above).
- **UI conventions:** no emoji in UI (real icons = hand-written inline SVG, see `AwardIcons.tsx`); player-facing prose is casual/second-person, sentence-cased, no em-dashes.
- **Crash visibility (2026-07-25):** `ui/components/ErrorBoundary.tsx` wraps the `<Outlet />` in `Layout.tsx` **keyed by `location.key`** (a page crash keeps TopBar/Sidebar mounted so the user can navigate away, and moving route remounts a clean boundary) plus an outer one in `App.tsx` for the routes outside `Layout` (`/leagues`, `/new-league`). `posthog.init` sets **`capture_exceptions: true`** (`main.tsx`) and the boundary also calls `captureException` itself, because React swallows the error on its way to unmounting. Before this, *any* throw blanked the whole app with the reason only in the console, and error tracking had **zero** issues recorded ever — a crash report could never be more specific than "it crashed". Gotcha for testing: **server rendering does not run error boundaries** (React re-throws to the caller), and there's no DOM test env in this repo, so `test/ui/errorBoundary.test.tsx` pins our half of the contract (`getDerivedStateFromError` + the fallback render) rather than a live catch. `test/ui/transfersRender.test.tsx` is the render harness pattern for a page (mock `useLeague`, wrap in `MemoryRouter`, `renderToStaticMarkup`) — a throw there surfaces as a test failure.

Measured over 15 seeded seasons: margin 1 → 78.7 champion pts, 2.5 → 80.8, always-sub → 79.8. Note the gate's own 5-season sample is noisy (single seasons swing 70-87), so it sits near its floor by construction — **re-measure over ≥15 seasons before reading a small move in it as a regression.** The gate is also **form-aware** (`SUB_GATE_RATING_INFLUENCE`, `liveRatingFor`): the tired starter's live `computeMatchRating` (vs the 6.0 baseline) shifts `tiredValue` — a starter playing well is harder to justify hooking, one playing poorly easier — reusing the same signal `subPriority` uses for the who-comes-*off* pick. The form term is mean-zero around baseline, so it redistributes *which* subs are held without moving the ~1-in-10 aggregate; rebased the scoreline hash a second time (intended). `MatchPlayer` now carries `ovr` for this. See **Roster & tactics** for the user "more minutes" flag.

## Feature ledger (post-M6, all shipped)

Each entry: what it is / where it lives / gotchas.

**Roster & tactics**
- **Starting XI** — user drag-drops between XI and bench, persisted as `StoredTeam.starters` (11 pids, `null`=auto). `resolveXI` (`core/lineup/resolveXI.ts`) falls back to `selectXI` auto-pick when invalid. Only the user's club sets `starters`; AI always auto-picks.
- **Formations** — 9 shapes in `FORMATIONS` (`core/lineup/formations.ts`), `StoredTeam.formation` (default `4-3-3`). A real tactical lever: the match sim rolls up composites from the XI each club's formation fields (`teamFormation`/`teamSlots`). AI clubs auto-pick their strongest shape (`chooseBestFormation`, refreshed end of each transfer window via `assignAIFormations`; never the user's). The user can opt into the same pick via a **"Best XI"** button on Roster (`autoPickBestXIAction` in `LeagueContext`, runs `chooseBestFormation` on the user roster + clears `starters`). `PitchField.tsx` + `pitchLayout.ts` render per-formation layouts.
- **ROSTER_CAP** (30, `core/constants.ts`) blocks user FA signings/buys when full; youth intake/AI FA unaffected (AI trimmed to 25 each offseason).
- **"More minutes" flag** — user flags bench players via `StoredTeam.moreMinutes` (pids; user-only, `setMoreMinutes` in `core/lineup/moreMinutes.ts`, Roster bench-row toggle). Carried through `simThrough`→`leagueMatchData` onto each bench `MatchPlayer.minutesBoost`; in-match, a flagged player gets a `SUB_MINUTES_BOOST` ovr credit in the sub decision (helps him win the "who comes on" pick and clear the bench-quality gate) plus a dedicated boost-driven sub path in `attemptSub` that subs him for the weakest on-pitch player at his position. A nudge, not a force — the gate still blocks a clearly-worse flagged player. Migrated (backfills `[]`).

**Match data & stats**
- **Box scores** — `PlayerMatchLine`/`SeasonStats`. **Match Rating** (`engine/matchRating.ts`, FotMob-style 0-10, position-weighted, damped by minutes). `minutesPlayed` reconstructed from event clocks. `tackles`/`interceptions` split (`pickInterceptor`). Decorative `passes`/`crosses`/`foulsCommitted` attributed post-sim on a separate rng stream (scoreline-invariant). `avgRating` rolled into `SeasonStats`.
- **Multi-season history** — `Player.stats[]` is append-only (never pruned), so Leaders browse any past season for free. `LeagueStore.seasonHistory` stores each completed season's final table + champion + awards (Standings had no other persisted history — `league.played` is wiped each offseason). Leaders "All Seasons" adds Career vs Single-Season scope.

**Awards & history**
- **End-of-season awards** — `core/awards.ts` (`computeSeasonAwards`, pure/re-runnable). POTY, Golden Boot, Team of the Season. Formulas layer explicit stat weights + an `ovrBonus` (via `ovrDuringSeason`, reads `Player.hist` not present-day ovr) on top of `avgRating`. `/awards` page; Dashboard "Advance" navigates there post-offseason.
- **Worldwide awards — Ballon d'Or + World Team of the Year** (`core/worldAwards.ts`, `computeWorldAwards`, pure/re-runnable/rng-free) — the whole world judged as one field, stored as `SeasonHistoryEntry.world` (`WorldAwards{ballonDOr: BallonDOrEntry[10], worldTeamOfYear}`), surfaced on `/awards`'s **World** tab (per-competition awards move under a "By league" tab) and in Player Profile honours. Score = domestic POTY/TOTS score **+ a league-strength correction** + Continental Cup + international + league title, each part kept on the entry so the UI can show *why* he won.
  - **The league-strength correction is the load-bearing bit.** Match ratings z-normalize *within* each competition, so an uncorrected worldwide award goes to whoever plays in the weakest league (dominating weak opposition scores identically). `leagueStrengthOffsets` adds `(comp mean ovr − world mean ovr) × WORLD_AWARD_LEAGUE_STRENGTH_WEIGHT` (0.05). Ovr is the yardstick precisely because it's the one player number that *isn't* normalized. It's a **unit conversion, not a difficulty knob** — 0.05 is the empirical rating-per-ovr slope inside a league; inflating it over-corrects and makes a strong league's mid-tabler outrank a weak league's best. Tier 2 needs no special-casing: its mean drags its own offset down.
  - **Cup ratings take no correction** — cup matches normalize against the whole pooled 20-club field (`cupMatchData`), making them the only directly cross-league performance number the sim produces. Cup run bonus is keyed by `cupRoundsFromFinal` (`cup/cup.ts`, counts *backwards* from the final so Swiss round 0 = QF and legacy round 0 = R16 don't collide), pro-rated by appearances so a bit-part player doesn't collect a winner's share.
  - **`WORLD_AWARD_CUP_MULTIPLIER` is 1.0, and the intuition that says it should be higher is measurably wrong.** It shipped at 1.5 on "cup goals are rarer, so worth more". They aren't: only elite attackers on the best 20 clubs play the cup, so its per-game scoring rate *matches* the league's (same player, 13 goals in 8 cup games vs 25 in 38 league games), and a premium double-counts. At 1.5 (with rating weight 0.5, run bonus 0.6) the cup component spanned 0-3.1 against a league component spanning 2.4 — nine games outweighing thirty-eight — and 2 of 8 audited seasons crowned a player with a *below-6.8-average* league season. Now 1.0 / 0.2 caps the cup's *individual production* term. Measured effect: winner's median world-ovr rank 259 → 123, and the 85-ovr rank-2 player correctly beat the 73-ovr rank-408 cup runner. **Residual, known and accepted:** the winner is ~top-100 of ~4,200 who played rather than top-20, because the shared `AWARD_OVR_WEIGHT` (0.06) is deliberately small so a big statline can edge out a higher-ovr player — the same trade the per-league POTY makes. Raising it would change the existing league awards too, so it wasn't touched unilaterally.
  - **Team achievement is weighted separately from individual cup production, and deliberately much higher (2026-07-27, user call).** `WORLD_AWARD_LEAGUE_TITLE_BONUS` 0.3→**0.8**, `WORLD_AWARD_CUP_RUN_BONUS` [0.35,0.2,0.1,0.05]→**[1,0.55,0.3,0.15]**, `WORLD_AWARD_WORLD_CUP_BONUS` 0.6→**1.4**. Sized by an explicit exchange rate against `POTY_GOAL_WEIGHT.FWD` (0.08): title ≈ 10 goals, cup ≈ 12, World Cup ≈ 17 — the intended hierarchy is World Cup > Continental Cup > league. **Raising these is not the same risk as raising `WORLD_AWARD_CUP_MULTIPLIER`**: a run bonus is uniform across a squad (modulo `involvement` pro-rating), so it can only move the award *between* clubs, never inflate a player above a better team-mate. The failure mode to watch is therefore "the award became a prize for being on the best team", measured as winner's world-ovr rank. Measured at the time, *before* `WORLD_AWARD_OVR_WEIGHT` existed, over 20 seasons (2 seeds × 10): winner won his league 55%→**65%**, wins the Continental Cup **40%**, World Cup winner in **2 of 5** tournament years; cost was winner's median world-ovr rank 61→108. **Those trophy rates were then partly given back by `WORLD_AWARD_OVR_WEIGHT` below — see its sweep for the numbers that actually ship.**
  - **`WORLD_AWARD_OVR_WEIGHT` (0.14) is an EXTRA ovr term applied by the world awards only**, stacked on top of the `AWARD_OVR_WEIGHT` (0.06) already inside `potyScore`/`totsScore` (2026-07-27, user call). Deliberately a *second* constant: the shared one also drives the per-league POTY / Golden Boot / Team of the Season, so raising it would silently retune three shipped awards to fix a fourth. Principled as well as convenient — every other input is z-normalized within its competition, making ovr the only cross-league-meaningful number, the same property `leagueStrengthOffsets` relies on. **It trades directly against team achievement, and the trade is inescapable:** at 0.14 the winner's median world-ovr rank is **8** (mean 31, worst 150, from 108/210/882), but Continental Cup wins fall 40%→**15%**. Scaling the team bonuses up ~1.8× to compensate restored trophies *and put the rank straight back to median 61* — both levers reorder the same ranking, so raising them together just cancels. The full sweep table lives on the constant. **Do not "fix" the cup rate by raising the team bonuses; that has been measured and it cancels.**
  - **The Ballon d'Or is structurally a striker award — a formula property, not a tuning accident, and only partly mitigated.** Its base is `potyScore`, which contains **no defensive stats at all** (tackles/interceptions/saves live only in `totsScore`), so a CB's entire case is `avgRating` + the ovr terms. The higher per-goal weights for defenders (0.14 vs a striker's 0.08) can't compensate, because they multiply a stat defenders barely accumulate: a striker's 26 goals are worth 2.08 points while `avgRating` across the whole winner pool spans just 6.75–7.49. Before `WORLD_AWARD_OVR_WEIGHT` the split was **75% ST and 0% CB/DM/CM/GK — no defender, holding mid or keeper ever reached the top 10**; at 0.14 it is **45% ST / 30% AM / 20% W / 5% FB**, i.e. raw quality is now the only route in for a non-attacker. A real fix means giving the Ballon d'Or its own formula with defensive terms instead of reusing `potyScore` — a design change, not a retune, so it is left for a user call. The World XI is unaffected either way (fixed 4-3-3 slots off the balanced `totsScore`).
  - International reads `Player.intl.seasons` for the same season (the campaign played in the offseason *after* it — international runs at the top of `simOffseason`, so it's already credited when awards compute). Old saves have no per-campaign lines → score 0 there rather than guessing from career totals.
  - Computed in `simOffseason` step 3.6 (needs the tables for the title bonus) off **`league.players`**, untouched by progression, and `league.cup` before it's archived. Migrated: `migrate.ts` **backfills every past season** (context is all snapshotted on the history entry + `cupHistory` + `international.history`); same caveat as the existing award backfill — retired players are out of the pool, so old seasons are judged on survivors.

- **GOAT rankings** (`core/frivolities/goat.ts`, default tab) — `playerGoatRanking`/`teamGoatRanking`, a **first-draft, taste-based formula** whose every weight lives in the `GOAT_*` block in `constants.ts` and is meant to be argued with. **Feeds nothing in the sim.** Player score = peak + prime + longevity/rating + awards + trophies + production, returned as `components: GoatComponent[]`, each carrying the `GoatTerm[]` (`count`/`weight`/`points`) behind it, so a row expands to its full arithmetic; the table generates its columns *from* `components`, which is what stops a component counting toward the score without appearing (that shipped once). **Rounding happens once per component, never per term** — a term must show exact `count x weight` or a reader sees "24 x 0.15 = 4" and stops trusting the board — while whole-number components still sum exactly to the whole-number score, so columns always reconcile with the total and the ranking can't display out of order; `prime` (area under his career ovr curve above `GOAT_OVR_BASELINE`) is weighted to out-earn `peak` over a long career, which is the distinction the formula exists to make. Club score = trophies (dominant) + consistency (top-4 finishes, top-flight seasons, and per-season ppg surplus over `GOAT_TEAM_PPG_BASELINE`, halved in tier 2 so dominating a division you shouldn't be in isn't a case). **AI General Manager** (replaces rule-scripts with emergent evaluation; full brief in the user's "AI GM Philosophy" doc)
- **Evaluation core** — `core/ai/clubContext.ts` (`deriveLeagueContexts`: squad strength/age/depth + league-normalized **ambition**/**frugality** scalars, *derived from state, not stored*) and `evaluate.ts` (`valueToClub` layers positional-need/timeline/affordability on `trueTransferValue`; `perceivedValueToClub` adds scouting-noise scaled by frugality). Normalization is scoped **within each competition** — *except* `stature` (see below), which is deliberately world-wide.
- **Buy-side vs keep-side valuation (`ValuationSide`, 2026-08-08) — load-bearing, was the single worst realism bug.** A club must not price its own players with the buy-side formula: that formula asks *how much would he upgrade us*, so a club's own best player at a position scores **zero** (he *is* `posBestOvr` — he's measured against himself), the depth term reads *surplus* because he's one of the bodies, and affordability marks him down again for a purchase that isn't happening. Net effect: **the worse a club was, the more it valued a star**, so a superstar's own club was always his *lowest* valuer and he was permanently cheap + available. Measured on a real world: an 85-ovr player's own club (squad 75.0) valued him at **$132M** against a $350M market, while the five highest bidders were the *weakest* clubs alive (a squad-51.9 side valued him at **$538M**). `keepValueToClub` fixes it counterfactually — "how far would we fall back without him": incumbent = `posSecondBestOvr` (new `ClubContext` field) when he's the club's best, depth counted as `depth-1`, **no affordability**, and timeline takes `max(prime, youth)` so a win-now club can't write off its own 21-year-old. Used for every *reservation* price (`runAITransferMarket`, `inboundOffers`, both `loans.ts` sites). **Renewals deliberately stay buy-side** — `AI_RENEWAL_MARGIN` is calibrated against those numbers, and keep-side values re-sign essentially everyone and *starve free agency* (measured: `runAIFreeAgency` signed nobody at all). Revisit only with `AI_RENEWAL_MARGIN` retuned in the same change.
- **Player will (`core/transfers/playerWill.ts`, 2026-08-08)** — the missing *other half* of a transfer. Every valuation is a club's view; nothing represented whether the **player** wants the move, which is why stars poured downhill. Football has no salary cap to justify a star at a small club (basketball does — cap space genuinely sends stars to small markets), so this supplies the constraint. `ClubContext.stature` ([0,1], squad strength vs an **absolute** band blended with hype — the one normalization that is *not* per-competition, because "is this a step up" is a global question and the biggest club in a weak league is still small). `moveAppeal` scales a **buyer's** valuation by how much the player likes the destination, weighted by `statureSensitivity` (a ≤62-ovr squad player is indifferent; a ≥78 star weighs it fully); a big enough step down is a flat `refusesMove`. `settledMultiplier` scales a **reservation** up for a player who just arrived, decaying over `PLAYER_SETTLED_SEASONS` — `joinedSeasons` derives arrival from `league.transfers` (loans/loan-returns excluded), so **no persisted field and no migration**. **Pure functions, zero rng draws**, and both market gates sit **after** the jitter draw (same rule as the Division-2 guard) so RNG stream order is untouched. Applies to the **user identically** (`refusesMoveToClub` in `makeTransferOffer`/`acceptCounterOffer`/`recommendedTransfers`/world search's `notForSaleReason`) — exempting the user would just hand them the exploit.
- **AI↔AI market** (`core/ai/transferMarket.ts`) — a player's reservation is his value to his current club; he moves to whoever values him enough more to clear it and afford the fee. Guardrails: min-surplus, per-window buy/sell caps, depth floor, cash reserve. Runs once per window. **There is deliberately no availability screen — protection is by price, not veto (2026-08-11).** `AI_MARKET_AVAILABILITY` used to skip any player whose keep-side reservation exceeded his club-blind market value; those quantities aren't commensurable, and keep-side is *built* to exceed market for a club's own best player, so of 239 clubs the number whose best player could ever be offered was **zero**. That shut off the upward drain of talent that counteracts `growthDamping`, and the strength ladder inverted outright — England finished *below* Portugal over 20 seasons on shipped main. An irreplaceable player is now protected by a high reservation the buyer must clear, not by exclusion. **Any replacement prune must bound the best possible buyer valuation against the reservation; comparing to market value reintroduces the bug.** Cost of having no prune: one market run is ~52ms → ~357ms on the **240-club** world it was measured on (`scripts/marketTiming.ts`), in the worker. **It scales worse than linearly with world size, so re-measure after adding a country rather than reusing the number** (it was also originally mislabelled "320-club" here): the pre-filter was the only early-out ahead of the O(teams) buyer loop, so cost grows with candidates × clubs. **Measured on the 16-competition/320-club world: ~1611ms per run, 560 deals** — 4.5× the 240-club figure for a 1.33× club count. At two windows a season that is ~3.2s per season against ~0.1s when the filter existed, roughly **9% of a season-cycle's sim time** (~34s) versus well under 1% before. Still in the worker, so it does not block the main thread, but this is now the strongest argument for a *sound* replacement prune — which must bound the best possible buyer valuation against the reservation, never compare to market value. Full diagnosis: `docs/transfer-mobility.md`. **Need-buy path** (`AI_NEED_BUY_*`, `hasPositionalGap` in `evaluate.ts`): the normal `AI_MARKET_MIN_SURPLUS` gate only fires on *bargains*, which left cash-rich clubs banking money while a position went unfilled. When a buyer has a genuine positional gap there (understaffed vs `ROSTER_COMPOSITION`, or a weak startable hole this player upgrades), its required surplus margin drops to `AI_NEED_BUY_MIN_SURPLUS` (0 = pay a fair price, no discount) and it frees up part of its frugality-driven reserve (`AI_NEED_BUY_RESERVE_RELIEF`, never below `AI_MARKET_RESERVE_FRACTION_MIN` → no deficit). Elites stay unbuyable (priceless-star premium is in valuation, untouched); it only routes affordable, already-available squad players to clubs that need them (a move, not a creation → no inflation risk). **The need-buy path is not an exception — it is 92-93% of all executed deals, and that is load-bearing (measured 2026-08-12, `scripts/needBuyMarginProbe.ts`).** `hasPositionalGap`'s understaffed branch tests `posDepth < ROSTER_COMPOSITION`, a *stocking* target that sums to 25 against squads trimmed to 25, so a squad not distributed exactly to target is short somewhere and essentially every club always is. That reads as a loose predicate; it was tightened two ways and **both were rejected**. Depth (a hole = "cannot field the position", half the target — which is also `keepsDepthFloor`'s threshold) hit its target cleanly, 92%→34% with the ladder green on all four seeds, and put **2 of 4 seeds into deficit** (Belgium −£2.7M s16, Turkey −£1.9M s17) where main has none: Belgium lost a third of its *sales* but two thirds of its *income*, because a strong club buying a weak league's star qualifies via *understaffed* (it is strong everywhere, so the weak-starter branch never fires for it) and depth is quality-blind, so it cut the valuable upward sales along with the filler. A quality gate instead (a shortage counts only if the player addresses it) was principled and **inert**, 92.3%→91.5%, since a buyer only bids on players it already rates. **The generalisation, which outlives this predicate: the weak leagues run on transfer receipts** — Belgium's 20 clubs take ~£1.1bn in a *single window* against ~£800M of base income for the whole league across a season (`BASE_SEASON_BUDGET` × `COUNTRY_BUDGET_SCALE`) — so **anything that reduces market volume lands on the same tripwire**, including the sound buyer-loop prune wanted for performance, a need-to-sell term, and a floor on `AI_NEED_BUY_MIN_SURPLUS`. Two process notes: **deal count is the wrong yardstick, receipts into the poor leagues is the right one** (dropping a hundred £1M filler deals is harmless, dropping a few big upward sales is not, and counts can't tell them apart — the probe prints receipts by league for exactly this); and **the finance column fails first, not the ladder** — the change that bankrupted two seeds passed every ladder check, so watching only strength would have shipped it. Full diagnosis: `docs/transfer-mobility.md`.

**Finance**
- `budget` is a **cumulative running balance**, never reset to base — light spending compounds. Bounded by `budgetCap(tier, hype)` (`core/finance/budget.ts`): hype-scaled ceiling between `MAX_BUDGET_FLOOR` and `MAX_BUDGET`, ×`financeScale` per country/tier. Banking past the cap destroys the excess (never causes a deficit).
- Wages: cubic in ovr (`seasonSalaryForOvr`, `core/contracts.ts`), charged **up front** at season start (`chargeSeasonStart`); season-end `settleSeasonEnd` handles prize + hype − scouting only. Mid-season acquisitions charge full season salary at acquisition.
- **Value scale retuned to the game's own economy (2026-08-08).** `VALUATION_OVR_COEFF` 56_000→**32_000** and `VALUATION_ELITE_COEFF/EXPONENT` 11_000_000/2.5→**1_200_000/2.0**. The old curve was pinned to real Premier League *fees* while `BASE_SEASON_BUDGET` is $88M (a real club turns over several times that), so a "realistic" $120M fee cost ~1.4 seasons of a club's entire income vs ~0.2 for the real deal it copied — every transfer was proportionally ~8x the real market. Worse, the elite term **saturated**: at ovr 80 it alone was $352M, so *every* player ≥80 priced identically at the `MAX_TRANSFER_VALUE` clamp and (via `AI_MARKET_FEE_FLOOR_FRACTION` 0.5) every elite deal opened at $175M. Measured: **42 fees ≥$100M per season**, whose median subject was ovr 75 / age 22. New base+elite curve: 65≈$21M, 70≈$32M, 75≈$48M, 78≈$59M, 80≈$86M, 83≈$134M, 85≈$186M, 87≈$241M — a real gradient, clamp reserved for the freak. Also `AI_MARKET_AVAILABILITY` 1.05→**0.95** (above 1.0 a club shopped players it rated *above* market, the opposite of "surplus") — **that tightening was reverted by deleting the constant outright on 2026-08-11; it inverted the strength ladder. See the AI↔AI market entry above and `docs/transfer-mobility.md`.** **Gate for any future change here: `scripts/marketRealismAudit.ts`** (star churn, downward moves, ≥$100M count, club solvency, FA-pool size). Beware the coupled constants — lowering values makes renewals *less* likely (value vs `salary × AI_RENEWAL_MARGIN`) and shrinks loan/`AI_MARKET_MIN_VALUE` eligibility.
- **Capped values + "protected star" not-for-sale gate** — the load-bearing **difficulty lever** (money buys a good squad, not a great one). Two parts: (1) an accelerating elite premium above `VALUATION_ELITE_THRESHOLD` (76 ≈ the top of a league) in `trueTransferValue` makes the real difference-makers expensive, but every value/asking price is **clamped at `MAX_TRANSFER_VALUE` ($350M)** so quoted fees stay believable — no more billion-dollar tags. (2) The genuine best players are removed from the market entirely rather than priced into the stratosphere: `core/transfers/protectedStars.ts` `isProtectedStar`/`protectedStarPids` withhold any AI player who was *best-in-world last season* (`ovr ≥ PROTECTED_STAR_OVR` 80, **or** won POTY/Golden Boot/a Team-of-the-Season place) **and** whose club finished **top-`PROTECTED_STAR_TOP_FINISH` (4)** of a **tier-1** league last season. Wired into `makeTransferOffer`/`acceptCounterOffer` (user buys), `recommendedTransfers` (hidden from targets), and `runAITransferMarket` (AI↔AI, via a `protectedPids` set passed by the caller). The gate is **data-driven off a completed-season record**, not the live league, because the offseason summer market runs *before* the `seasonHistory` entry is appended — that caller (`offseason.ts`) builds the record from the freshly-computed `standings`/`awards`/`compsByTid`; regular-season/winter callers use `lastCompletedSeason(league)`. The **user's own club is never gated** (you always control your sales). Note a global player-quality nerf can *not* substitute for gating the market, because match composites z-normalize league-wide quality away (proven — it left title-win rates unchanged).
- **Finance page** (`/finance`) — pure display of budget/hype, scouting slider, settlement breakdown, wage bill, transfer history, league-wide table.

**World / leagues** (competitions-as-data)
- `core/competitions.ts` — `Competition{id,country,tier,name}`, persisted `LeagueStore.competitions`. Teams carry `compId` (not a raw division number). Every "div 0 vs 1" pair is a loop over competitions. Finance fns take a `scale`, looked up via `financeScale`.
- `worldCompetitions()` = **16 competitions / 320 clubs**: England, Spain, Italy, Germany (equal siblings) + **France, Portugal, Belgium & Turkey (deliberately weaker + poorer)** via `COUNTRY_STRENGTH_OFFSET`/`COUNTRY_BUDGET_SCALE` (`constants.ts`). Weakness is invisible in a country's own matches (per-competition z-norm) — it bites only in finance (selling leagues) and the Cup (shared baseline).
- **Strength ladder is compressed, not literal (2026-08-08).** Offsets France 5 / Portugal 10 / Belgium 11 / Turkey 12 follow the real UEFA five-year coefficient *ordering*; the real gaps below France are only a few coefficient points, so mapping them literally would put Belgium ~17 and Turkey ~30 and generate unplayable squads. Each offset point ≈ **0.94 OVR** off a league's starters (measured). **`COUNTRY_BUDGET_SCALE` MUST stay monotonic with `COUNTRY_STRENGTH_OFFSET`** (France .7 > Portugal .5 > Belgium .45 > Turkey .4) — **a richer league climbs the ladder over a dynasty, so a weaker-but-richer league overtakes a stronger-but-poorer one.** Measured, not theoretical: Belgium/Turkey generate within 0.9 OVR of each other (a near-matched pair that isolates budget from everything else), and at Belgium .35 / Turkey .5 the ladder **inverted by 2.23 OVR over 20 seasons** — Turkey, generated weakest, finished *above* Belgium. Real squad values do invert here (Belgian Pro League €0.98B < Süper Lig €1.27B while Belgium outranks Turkey on the pitch); that is deliberately **not** modelled — the engine can't hold "weak but rich", and the ladder is load-bearing while the flavour isn't. **Gotcha when measuring this:** comparing leagues with very different starting OVR (England vs Portugal) hides the budget signal entirely behind progression's mean-reversion — an earlier attribution run did exactly that and wrongly concluded money was a weak lever. Compare near-equal leagues.
- **Weak-league solvency holds, and an AI wage-affordability gate was built for it and then removed as provably inert (2026-08-11).** History worth keeping, because the same fix will look attractive again. A deficit was reported, a `staysSolvent` gate was added to every AI buy path (transfer/loan/free agency) to project the next season-start charge with the incoming salary on the books, and it was measured "near-neutral, deficits 0 → 0". **All three of those measurements were taken on a market that could not sell a club's best player** (the `AI_MARKET_AVAILABILITY` bug — see the AI↔AI market entry). Once that was fixed, re-measurement showed: (a) *with* the gate, on the pre-fix market, **4 AI clubs still went negative on seed 1** (worst −£5.96M, first at **season 12**) — the gate never prevented the thing it was for, and the "0 → 0" claim survived only because it had been re-validated with a **5-season** spot check after the fee rescale; (b) on the fixed market, deleting the gate changes **nothing that matters**: 0 deficits across 4 seeds either way, and on 3 of those 4 seeds the entire 20-season dynasty comes out **byte-identical**. Identical output is a *proof* of zero firings on those seeds, not a coincidence — RNG stream order is load-bearing and a declined signing skips a contract-length draw, so one firing moves every downstream number. **It is therefore inconsequential rather than literally inert, and the distinction was nearly missed:** seed 3 *does* differ (France→Portugal +0.24 → +0.31), i.e. the gate fired there at least once and still prevented no deficit. An earlier version of this entry generalised "byte-identical" from the two seeds it had been measured on into a claim that the gate never fires at all; a fourth seed contradicted it. **Measure the seed you are about to generalise from.** **The real mechanism was never wages:** with the market shut, a club could not sell its best (and highest-paid) player, so wage bills ratcheted with no relief valve — which surfaced as insolvency in the finance column and a collapsing ladder in the ratings column, one cause with two symptoms. **Before rebuilding this gate, first check whether the market can still shed wages.**
  - **Margins, measured.** Opening budgets have real headroom: poorest club £15.8M (Belgium, seed 1) / £12.6M (Turkey, seed 2), via `scripts/genBudgetProbe.ts`. The thin point is *after season 1 is played* — £0.01M / £0.06M (Turkey) — driven by in-season spending, and it is the AI market's cash reserve that holds it above zero.
  - **The structural asymmetry is real even without a gate**: `financeScale` multiplies *income* (`BASE_SEASON_BUDGET`, prize payouts, hype revenue) while `seasonSalaryForOvr` is country-independent. Weak leagues stay solvent because `COUNTRY_STRENGTH_OFFSET` hands them cheaper squads *and* the market keeps draining their expensive players upward — nothing links those knobs, so re-check solvency after any change to either.
  - **Two audit methodology bugs found on the way, both fixed and both worth remembering:** (a) `weakLeaguesAudit.ts` sampled the budget only at generation and at the end while reporting "min AI budget over dynasty", so a mid-dynasty dip read as solvent — it now samples both points every season; (b) sampling *only* after `simOffseason` misses the true minimum, which lands **post-season** (after the winter window, before season-end settlement), not post-offseason.
- **Adjacent weak rungs are NOT separately resolvable across a dynasty.** Portugal/Belgium/Turkey are one offset point apart (≈0.9 OVR) and ~40% of that erodes, so they end within a few tenths (measured seed 1: 49.6 / 49.6 / 49.3) and their mutual order coin-flips on seed noise. The audit therefore gates *ordering* plus block-level spreads, **not** per-rung magnitudes — asserting the latter would be asserting precision the design doesn't have. If rungs ever need to be individually resolvable, widen to 2-point offset steps rather than tightening the audit.
  - **Order is gated at two scales, and the split is load-bearing (2026-08-11).** The audit used to state all of the above and then gate adjacent-rung order *per seed* at 0.5 — a tolerance **below the noise it had just described**, so it contradicted its own header and failed on seed choice alone. Measured 4 seeds × 20 seasons: Portugal→Belgium `+0.24 −0.44 +1.51 +1.75` (mean +0.77), Belgium→Turkey `−1.33 +0.48 −0.45 +0.06` (mean −0.31) — straddling zero with ~±1 OVR of spread. So a single seed now only catches a **gross** inversion (`SEED_INVERSION_TOLERANCE` 2.0) while a **systematic** one is caught on the **mean across seeds** (`MEAN_INVERSION_TOLERANCE` 1.0), where noise averages down; both real failures (the 2.23 budget inversion, the 2.5 market inversion) are present on every seed and so fail both gates. `SEEDS` therefore defaults to **four**, and the script says so when run with fewer than three, because a mean of two draws is not worth gating on. **Don't "fix" a red adjacent rung by tightening the per-seed tolerance — that is the bug this replaced.**
- **Country strength gaps erode ~43% over a 20-season dynasty, and it's `growthDamping`, not the market (2026-08-08).** Measured by attributing drift to its only two sources (ovr changes *only* in progression, so retained players' mean change is pure progression and the remainder is pure churn): progression gave England +4.06 vs Portugal +7.53 — a **3.47 OVR relative lift for the weaker league** — against churn's 0.55. Cause: `growthDamping` throttles positive growth above a **global, absolute** `GROWTH_DAMPING_START` (65), so a league sitting under that line grows undamped while the big four are throttled. **Do not "fix" this by making the threshold league-relative** — that hands every weak league its own elites, which is the inflation the equilibrium exists to prevent; `GROWTH_DAMPING_END`/`FLOOR` were swept against a 30-season × 3-seed audit to land D1's 80+ population at 8-16 and re-verified over 100 seasons. `scripts/weakLeaguesAudit.ts` now **asserts a minimum surviving gap per rung** (and exits non-zero) rather than mere rank order — the old ordering-only check passed cleanly while the England→Portugal gap fell 9.6 → 5.5.
- `generateWorld()` — one rng pass; England block is byte-identical to the old England-only generation, and each country is generated in table order so appending one never perturbs an existing country's players (verified: adding Belgium/Turkey left all six prior leagues' generated OVR identical). `createLeagueState` uses it for all new saves; old saves stay at whatever country set they were created with (never re-run generation). `CLUBS` = 320 fictional identities (no real clubs — trademark caution). New-save UI has a country picker (`NewLeague.tsx`); Customize Teams editor is competition-scoped.
- **Per-league nationality tables must exist for every home country** (`LEAGUE_NATIONALITY_WEIGHTS`) — a missing country silently falls back to *England's* table. Source percentages routinely over-sum (the supplied Belgian list totalled 116.5%, the Turkish 130.7%); since the engine normalizes to the table total, feeding them raw understates the domestic share badly (Turkey would land 36.7% domestic instead of 48%). **Scale the foreign block so the domestic share lands on its stated value.** New nationalities named only by a new league's table go in **`UNLISTED_NATIONALITIES`**, never `OTHER_NATIONS` — `TAIL_BASE` is built from `NATIONALITIES` + `OTHER_NATIONS` only, so the latter would re-weight the "Rest of the World" tail draw for every league in every existing save (Belgium needed none; Turkey added Bosnia-Herzegovina/Gambia/Albania).
- **Per-league nationalities** — `LEAGUE_NATIONALITY_WEIGHTS` (`core/players/nationalities.ts`), real top-flight breakdowns; drawn on each player's isolated identity sub-stream (RNG-safe). Youth intake is country-aware.

**Promotion/relegation & the second division**
- New leagues generate a full tier-2 division per country; 3-up/3-down straight swap each offseason (`core/promotion.ts`, `computeCountrySwaps`/`applyCompetitionSwaps`, per-country). A swapped club's `academyBase` converges gradually (`stepAcademyBaseConvergence`); finance scale switches immediately.
- **`enforceDivision2Ceiling`** (`core/ai/divisionCeiling.ts`) — the load-bearing anti-drift mechanic. Every offseason, any AI-controlled tier-2 player ≥ `DIVISION_2_REFUSAL_OVR_THRESHOLD` (70) is *deterministically* reassigned to a needy tier-1 club **in his own country** (zero fee, releases the receiver's weakest if capped). Runs twice (after promotion/relegation, and after the summer market). **Its workload dropped sharply on 2026-08-08** (61→18 sweep moves in the `offseason.test.ts` fixture) because the market no longer sells good players into tier 2 — worth knowing because the sweep's collateral (releasing a capped receiver's weakest man) was the *only* source of free agents in the very first offseason, so that test now plays a second season to reach steady state. This holds "D2 strongest ≤ D1 average" flat across 100-season dynasties — probabilistic approaches did not (relegation doesn't route through any market decision). `wouldRefuseExtension` (`core/ai/breakoutRefusal.ts`, now a flat ovr≥threshold check) is kept for **user-facing** purposes only (Roster "Wants a move to Division 1" badge/Extend-block; surfacing rival stars as buyable). **Continental Cup** (`core/cup/`) — **Swiss league phase + knockout** (all new cups)
- **20-club field**, qualified by league position (not OVR): strong (big-four) leagues send top 4, weak (France/Portugal) leagues send top 2 (`CUP_STRONG/WEAK_LEAGUE_SLOTS`). **Skips season 1** (no prior table → `cup===null`). Cross-cut by a **shared normalization baseline** (`simThrough`'s `cupMatchData` now pools the whole 20-club field) so weak clubs read as genuinely weaker. `LeagueStore.cup`/`cupHistory`, `/cup`.
- **League phase** (`core/cup/leaguePhase.ts`) — one combined table, each club plays `CUP_LEAGUE_PHASE_GAMES` (6) games. The draw (`drawLeaguePhase`) splits the seeded field into `CUP_LEAGUE_PHASE_POTS` (2) strength pots and builds the schedule **directly as 6 edge-disjoint perfect matchings** (guarantees once-per-round; a build-then-color graph may not be 1-factorable), giving each club 3 opponents from each pot, no same-league pairings, an Eulerian home/away split. Runs on its own seeded rng per round (`LEAGUE_PHASE_STREAM` offset) so league scorelines stay bit-identical. Table tiebreak: pts→GD→GF→wins→seed (no head-to-head, Swiss-unreliable).
- **Split** (`splitLeaguePhase`): top `CUP_LP_DIRECT_QF` (4) → straight to QF; next `CUP_LP_PLAYOFF_TEAMS` (8, ranks 5–12) → single-leg **playoff** (5v12…) for the last 4 QF places; rest (13–20) eliminated. `seedKnockoutFromLeaguePhase` seeds the `CUP_KO_SIZE` (8) bracket when the LP completes.
- **Knockout** is format-aware (`isSwissCup`/`koRoundsOf`/`koRoundMatchdays`/`koLegMatchdays`/`koPrizeByRound`/`koFinalRound`): Swiss = QF→SF→Final (3 rounds). **QF/SF are two-legged, home-and-away, decided on aggregate** (`CupState.twoLegged`, true for all newly-built cups; final and playoff always single-leg). Level after regulation (90' single-leg, or aggregate after both legs) → extra time → shootout; LP games can draw. **The two legs are played on separate matchdays** (`CUP_KO_LEG_MATCHDAYS` = `[[29,31],[33,35],[37]]`: QF legs 29/31, SF 33/35, Final 37). Flow (`playKnockoutLeg`, dispatched by `dueCupLeg` → `{round, leg, twoLeg}`): the first-leg matchday plays all first legs (`playFirstLeg`, plain 90') and holds them in `CupState.koLegs` (no prizes, no bracket advance); the second-leg matchday resolves each held tie on aggregate (`resolveTwoLeggedTie` plays leg 2 with the host swapped, sums scorelines, ET/shootout if level), appends the finished `CupTie`, clears `koLegs`. `mergeLines` folds both legs' box scores into one so cup stats/UI see a single tie line; `CupTie.legs` carries the two 90' scorelines for display. Safe to spread across matchdays because cup matches don't carry fatigue/injuries between each other (own per-matchday composites); the home/away swap + doubled sample is what reduces cup-vs-domestic variance (single-leg knockouts between good teams are near coin-flips — measured, stronger club advance rate ~64%→70% at a strong-favorite edge). Each leg runs on its own seeded stream (`hashInts(lid,season,round,30,leg)`), so the league match stream is untouched. **`simThrough` halts before the user's final** (Dashboard warns; the single-leg final's matchday is unchanged at 37). Prizes: participation (LP) + playoff-win + per-KO-round (prize-only, credited when the tie finalizes). Cup stats live on each tie's `BoxScore` (LP matches carry their own `boxScore`), separate from `SeasonStats`; Player Profile Cup tab. The user's Schedule page lists their cup fixtures (LP/playoff/each KO leg) alongside league games.
- **Legacy cups** (pre-Swiss saves, `leaguePhase===null`): old 16-team straight bracket + `CupPlayIn` kept alive only so an in-progress old cup finishes; `migrate.ts` backfills `leaguePhase`/`playoff` to null and `twoLegged` to false (so any cup already in progress finishes single-leg; the next built cup is two-legged). New cups (built each offseason via `buildCupState`) are always Swiss + two-legged. Matchday layout — two-legged Swiss: LP `[3,7,11,15,19,23]`, playoff `27`, KO legs `[[29,31],[33,35],[37]]`; single-leg Swiss (old in-progress saves): KO `[31,34,37]`; legacy bracket: `[8,16,26,34]`.

**International football** (`core/international/`) — national teams, played entirely inside the offseason
- **Four-year cycle, watch-only** (`INTL_CYCLE_YEARS`=4, `qualifyingLeg`/`isTournamentSeason`). Keyed off `season % 4`: seasons 1/2/3 of a cycle each play one qualifying leg, season 4 (`% 4 == 0`) plays the `INTL_FIELD_SIZE` (16) team `World Cup` (4 groups of 4 → `INTL_KO_SIZE` (8) bracket, QF→SF→Final reusing the Continental Cup's `seedOrder`/`resolveCupTie`). **Qualifying is ONE campaign drawn once (at the cycle's first qualifying offseason, `qualifyingLeg==0`) and played a leg at a time across the three offseasons** — the campaign persists on `LeagueStore.international.qualifying`, accumulating results, and its 16 qualifiers are computed (`computeQualified`) only when the third leg completes; the tournament offseason then draws the World Cup from them. Each leg is seeded independently off the campaign's start season + leg index (`playQualifyingRound`), so leg-by-leg play is deterministic. Squad pids are filtered to living players each leg (a 3-season campaign outlives some players named at draw — `leagueMatchData` would deref a retired pid otherwise). No user management of any nation — squads auto-pick (`selectSquad`: best 23, ≤3 GKs, fit players before injured; `chooseBestFormation`). `LeagueStore.international` (`{qualifying, tournament, history, qualifyingHistory, powerRankings, stage, stageInjuries}`).
- **Played in stages the user clicks through, *before* the offseason advances (`core/international/staging.ts`).** The campaign is *drawn* the instant the club season ends (in `simThrough`, at the offseason transition — `initInternationalCampaign` names squads + draws groups/bracket, fixtures unplayed) and then *played* one stage at a time (`playIntlStage`): a qualifying offseason plays this cycle's one qualifying leg; a tournament offseason is group stage → QF → SF → Final. (A qualifying campaign is drawn only in the cycle's *first* qualifying offseason; the next two resume the in-progress campaign for their leg — see the four-year-cycle bullet above.) `InternationalState.stage` (`"qualifying"|"groups"|"qf"|"sf"|"final"|"done"|null`) tracks progress; the Dashboard's "Advance" button is replaced by the stage buttons (`isIntlStagePending`) until it reaches `"done"`. `simThroughInternational` plays every remaining stage at once (the "sim through" button, and the headless-test path). **The gate is presentational, not structural** — `simOffseason` *opens* by calling `simThroughInternational`, so it always completes a campaign the user left unplayed. That's what the Dashboard's **"Skip qualifying"/"Skip the World Cup"** button relies on: it just routes to `/set-scouting` (the normal advance), plays nothing itself, and lands identical results because the stages own their seeds (equivalence test in `international.test.ts`). **Each stage owns its seed** (`GROUP_STREAM`, `KNOCKOUT_STREAM + round`), so click-through == one-pass == old bulk result — `runQualifying`/`runTournament` are thin composers over the very same stage functions (equivalence test in `international.test.ts`). Init is player-free and shared-rng-free; every match runs on its own `hashInts` stream (`QUALIFYING/GROUP/KNOCKOUT/DRAW_STREAM` tags), **never the shared `rng`**, so club results stay bit-identical (`touchStats` hash + `simThrough` gate unchanged).
- **Now runs entirely *before* `simOffseason`, so retirement falls *after* the tournament** — a player about to retire gets one last campaign, and (as before) one injured in May still misses it, because squads read end-of-season ratings/injuries. Caps/goals/assists are credited per stage (additive `CareerDelta`); the one-off `tournaments`/`titles` counters and the `history` summary land at the Final. `simOffseason`'s old step 1.7 is gone.
- **A nation = a synthetic club.** `nationMatchData` builds `LeagueTeam`s keyed by `nid` (index into the campaign's `squads`, stands in for `tid`) and pools the whole field into **one** `leagueMatchData` normalization baseline — mandatory, exactly like `cupMatchData`, or z-norm flattens every nation to parity. `simMatchDetailed` runs unmodified.
- **Eligibility + fieldability.** A nation enters if pool ≥ `INTL_MIN_POOL` (18) with ≥ `INTL_MIN_KEEPERS` (1) GK **and** has a confederation (`confederationOf`). The GK floor is a *correctness* requirement: `selectXI` fills a GK slot with an outfielder when none exists, corrupting the keeping composite. ~39 of 75 name-pool nations clear the bar on a fresh world.
- **Confederations + slot allocation** (`confederations.ts`) — `CONFEDERATION_OF` maps every name-pool nation to one of 6 confederations (test-guarded: `international.test.ts` asserts no nation is missing). `allocateSlots` distributes the 16 places by largest-remainder **weighted by each confederation's count of *contender* nations** (the global strongest 16), floor 1, capped at nation count. Weighting by raw nation *count* was measurably wrong — Africa's 8 nations matched Europe's 24 for places while Europe held every strong side, filling the field with makeweights.
- **Qualifying is a three-leg round-robin** (`INTL_QUAL_LEGS`=3, `roundRobin(nids, legs)`), **one leg per qualifying offseason** — each fixture is tagged with its `leg` (0/1/2) at draw time (`IntlGroupMatch.leg`, optional for legacy saves → treated as 0), and `playQualifyingRound` plays the next unplayed leg via `playGroups(..., onlyLeg)`. A single round-robin left strong nations missing out on variance; three legs across three offseasons make a long, low-variance campaign that reads like real World Cup qualifying. Tournament groups stay single-leg (variance is the point). Serpentine group draw for qualifying (`serpentineGroups`), pot draw for the tournament (`potDraw`). `fillPlaces` walks group finishing positions (winners, then best runners-up via per-game-rate `rankAcrossGroups` since group sizes differ) so a confederation always fills its allocation.
- **Career record + injury carry-over; no rating/finance impact.** `Player.intl` (`IntlCareer`: caps/goals/assists/tournaments/titles, in `international/career.ts` to avoid an import cycle with `players/types.ts`) accumulated at sim time (`CareerDelta`), surfaced on Player Profile. **Nothing feeds progression or valuation** — cannot disturb the rating equilibrium. **Injuries do carry into the new club season** (`stageInjuries`, `collectInjured`, `carryIntlInjuries`): a knock in an international match sidelines the player for the opening weeks of the club season. Collected *post-hoc* from box-score injury events (never stamped mid-campaign → international match XIs/results are unchanged), held on `InternationalState.stageInjuries`, applied in `simOffseason` (step 3.05) **after** progression heals the club-season knocks, rolled on a dedicated seeded stream (`INTL_INJURY_STREAM`, never the shared `rng`). The rolled duration is reduced by `INTL_INJURY_OFFSEASON_RECOVERY` (2) — the summer break serves part of the recovery, so a short knock heals before kickoff and only a more serious injury carries, at a shortened spell. Note this is the *one* intended club-side effect: it changes club availability the following season, so multi-season league results after an international campaign are no longer bit-identical to a pre-feature baseline (single-season `touchStats` hash is untouched — `simSeason` never crosses an offseason). **Fatigue and value/hype bumps remain deferred** (would touch the equilibrium; need their own audit). Migrated: new arrays/`stageInjuries` backfill to empty, `Player.intl` absent = never capped.
- **"Light" archival + the National Teams section.** Only the *current* qualifying campaign and tournament are held in full; past editions collapse to compact self-contained summaries — **results, not box scores.** `IntlTournamentSummary` now carries final group tables (`IntlGroupTable`, nation-keyed via `groupTableSummary`) + every knockout scoreline (`IntlKnockoutResult`); `IntlQualifyingSummary` carries the qualifying group tables + qualifiers; both drop per-match box scores and squad lists (career totals on `Player.intl` are the lasting per-player record). `InternationalState` gains `qualifyingHistory`, `powerRankings` (an `IntlPowerSnapshot` — every eligible nation ranked by squad rating, taken each time a campaign is drawn in `initInternationalCampaign`), plus the existing tournament `history`. Archival happens at sim time: qualifying summary appended when qualifying finishes, tournament summary at the Final. Per-nation records (titles/finals/best-finish) are **derived**, not stored (`nationHistory.ts` `nationRecords`/`finishOf`). Old saves backfill the new arrays to empty and fill going forward (migrate.ts). UI: the **`/national-teams/*`** section (sidebar group, ordered *after* Team; `ui/pages/nationalTeams/`) — World Cup, Qualifying, **Rosters**, Schedule, Power Rankings, Stat Leaders (national teams + players filterable by country, off `Player.intl`), History. Navigation is sidebar-only (the pages carry no tab strip of their own). The old single `/international` page is gone (redirects to `/national-teams/world-cup`).
- **Rosters tab + per-campaign player record.** `Rosters.tsx` renders the live campaign's `NationSquad[]` — nation list sorted by squad rating, selected squad sorted by `sortByPosThenOvr` with the projected XI (`selectXI` off the squad's own formation) shaded. Squad pids missing from `league.players` are dropped, matching what `playQualifyingRound` feeds the sim (a 3-offseason campaign outlives some named players). **`IntlCareer.seasons`** (`IntlSeasonLine[]`, `career.ts`) breaks caps/goals/assists out per offseason played, `kind: "qualifying" | "tournament"` — surfaced as the Player Profile's third stats tab. Written by `applyCareerDelta`, which therefore takes `season`/`kind`; `season` is **threaded in from the caller** (`playIntlStage`/`simThroughInternational` gained a param) rather than read off the campaign, because a qualifying campaign's own `season` is the cycle's *start*, not the offseason being played. The squads-only call at the Final passes an empty delta and must not stamp empty rows — `mergeSeasonLine` only runs for players with a delta entry. Old saves backfill `seasons: []` (irreconstructable — archived campaigns hold no box scores); career totals stay the authoritative record. "Which campaign is current" is one shared helper (`liveCampaign` in `nationalTeams/shared.tsx`), used by both Rosters and Schedule: pending stage first, else **the more recent of tournament/qualifying by `season`** — "tournament if there is one" was stale, since a newly drawn cycle's qualifying outranks the previous World Cup. **Render volume is the qualifying schedule's gotcha:** a campaign is ~280 fixtures (39 nations, 7 groups, `INTL_QUAL_LEGS` legs), so Schedule filters to one round at a time by default (`currentLegOf` mirrors `playQualifyingRound`'s next-leg rule; "All rounds" opts back in), and `NationName` passes `tip={false}` to `Flag` — the tooltip only repeats the adjacent name and costs an absolutely-positioned shadowed span per flag (1674 → 186 flag nodes on that page).

**Career charts** (`ui/components/ValueHistoryChart.tsx`, `OvrHistoryChart.tsx`, shared `chartColors.ts`)
- **Transfer-value chart** on the **active** Player Profile (2026-08-12, replaced the OVR chart there): value on y, season on x, area colored by the club that season, crests at transfers, hover card with value / age / OVR / fogged POT / G-A / appearances / avg match rating / club. A **Value/OVR pill toggle** (`careerChart` state) swaps the same panel to `OvrHistoryChart` — kept because the two genuinely diverge (a veteran's rating holds flat while the age curve guts his value). **Retired** profiles get `OvrHistoryChart` alone (a retiree has no market value, and `ArchivedPlayer` carries no potential or contract to price one from).
- Crest tooltips on **both** charts go through `transferFeeLabel` — a bare `fee > 0` test rendered a loan and a loan return as "(free)", i.e. exactly the confusion that helper exists to prevent (pre-existing bug, fixed 2026-08-12).
- **Derived, not stored** (`core/finance/valueHistory.ts` `careerValueHistory`) — replays `trueTransferValue` over `player.hist`, so no schema change and existing saves chart their whole past immediately.
- **Season offset is load-bearing.** A `RatingsSnapshot` is stamped at the *end* of a season, so the one labelled N is what he carried through **N+1** — the same convention `awards.ts`'s `ovrDuringSeason` reads and `archive.ts` already bakes into `ArchivedSeason`. Points plot at `snap.season + 1`, which is also what makes the final point exactly his value today. The Profile's OVR/POT/attribute *table* deliberately keeps labelling rows by the stamp season (its footnote says so), so table and chart legitimately differ by one label.
- **`RatingsSnapshot.academy` does NOT take that offset** — progression reads it for the season that just *ended*, so it describes season N while the ratings beside it describe N+1. Shifting it would label a promoted youngster's first senior year "(Academy)". `careerValueHistory` therefore drops it; `PlayerProfile` resolves it per played season (`academyBySeason`, falling back to live squad membership for the current season, which has no snapshot yet). Caught in runtime verification, pinned by a test.
- **Contract term is held flat** at the player's *present* years-remaining for every point — old contract lengths aren't stored, so this keeps the curve a read on ability/age/potential (one constant multiplier) instead of distorting it with a guess.
- **POT goes through the scouting fog before pricing** (`pricedPotential` in `PlayerProfile`), or the dollar figure becomes an exact read on a hidden number (`trueTransferValue` pays a potential-gap premium). The fog band is taken once at `league.season` so its seeded jitter is one constant and the line stays smooth; the hover card still quotes each season's *own* band, matching the table.
- **One real point per season, drawn as a curve.** Ratings only move in the offseason, so there is no intra-season measurement — the line is a Fritsch–Carlson monotone cubic (no overshoot, can't draw a value he never had or dip below zero) sampled `SAMPLES_PER_SEASON` times and split into club-colored runs by nearest season. Hover always snaps to a season. y-axis is zero-based (money).

**Retirement** (`retirementProbability`/`isWantedForRetirement`, `players/progression.ts`; offseason step 3)
- **Age sets the curve's shape, last season's roster status sets its scale** (2026-07-28 rework; was age-only, identical odds for a 33-year-old star and a 33-year-old benchwarmer). Rostered → age curve × `RETIREMENT_ROSTERED_DAMPING` (damped, never zeroed: age still dominates). Unrostered → `RETIREMENT_UNROSTERED_BASE` at *any* age plus the undamped curve, so unsigned players drift out instead of sitting in the pool from 16 until 33. **Exception:** under `RETIREMENT_PROSPECT_MAX_AGE` **and** potential > `RETIREMENT_PROSPECT_POT_THRESHOLD` falls back to the damped curve, so high-ceiling kids between clubs aren't washed out.
- **The exemption's age bound is load-bearing.** `estimatePotential` seeds its peak at current ovr and only raises it, so `potential >= ovr` always. Without an age gate the exemption catches *every* unrostered player above ovr 65 — a released 37-year-old included — and hands him the damped curve (0.318 at 37 vs 0.53 under the old age-only model), i.e. it would make good unsigned veterans retire ~40% *less* than before the rework, and leave the ovr-66+ slice of the pool as the one population nothing removes (the cull spares it too, on `FREE_AGENT_CULL_MAX_PEAK_OVR`). Caught in review; a test pins it.
- **Both exemption bounds are pinned to the pool cull's constants by reference, not copied** (`RETIREMENT_PROSPECT_POT_THRESHOLD` = `FREE_AGENT_CULL_MAX_POT`, `RETIREMENT_PROSPECT_MAX_AGE` = `FREE_AGENT_CULL_MIN_AGE`), so the pair can't drift apart on either shared axis. They are **not** fully complementary: the cull also spares career peak > `FREE_AGENT_CULL_MAX_PEAK_OVR`, which retirement ignores on purpose.
- **"Rostered" means *last season*, snapshotted before step 1**, because retirement is step 3, step 1 has already released every expired contract into the free pool, and AI free agency doesn't re-sign anyone until step 4 — a live read retires a crowd of players about to be picked back up. Uses `freeAgentPids`, so academy players and players out on loan count as rostered.
- **Known gap in that grace:** it covers contract expiry (step 1, before free agency at step 4) but *not* mid-offseason releases. `trimRosterSurplus` (step 6) and `enforceDivision2Ceiling`'s weakest-player release both run *after* step 4, and `runAIFreeAgency` is offseason-only, so a trimmed player's first free agency is the next offseason's step 4 — which falls after his step-3 retirement roll. He is rolled once without ever having been offered. Fixing it properly means reordering the offseason (RNG-order consequences), so it is documented rather than patched; empirically it costs nothing measurable (min AI roster size *improved* and D1 mean ovr held).
- **One `rng()` draw per player either way**, so the shared stream's draw *count* is unchanged (outcomes move, which is the point). Retirees are stripped from `academyRoster` as well as `roster` — defence-in-depth only, still unreachable, since `freeAgentPids` counts academy players as rostered and the damped curve is exactly 0 below `RETIREMENT_START_AGE`.
- **Retirement scrubs live references but keeps history.** Retirees are dropped from `activeLoans`, `negotiations`, `inboundOffers`, `loanListings`, `loanRejections` — state pointing at a player who no longer exists (an un-scrubbed `activeLoan` would have `processLoanReturns` hand a dead pid back to its parent and log a phantom transfer). `transfers`/`newsEvents`/cup box scores are deliberately **kept**: unlike a culled nobody, a retiree had a real career. **Pre-existing consequence, made more frequent by this change:** those rows render as "Player &lt;pid&gt;" once he's deleted, and `awardedPids` protection (which the cull honours) does not apply to retirement, so an award winner who retires can leave an honours-board slot resolving to `undefined`. Both predate this rework; the honest fix is a retired-player archive, which is a design call.
- **Retirees are snapshotted onto the season-history entry, because they're deleted** (`core/players/retirements.ts`, `SeasonHistoryEntry.retirements?: RetirementSummary`, rendered as the Season Preview's Retirements section). `summarizeRetirements` copies name/nationality/pos/age/ovr/last club/career line/caps — a *copy*, not a pid reference, since the pid resolves to nothing a moment later (the same reason his surviving transfer rows read "Player &lt;pid&gt;"). Three gotchas: **(a)** the last-club map (`tidLastSeason` in `offseason.ts`) is built from the **pre-step-1** rosters, alongside the `unrosteredLastSeason` snapshot and for the identical reason — a live read files a fifteen-year club legend whose contract just expired as a free agent on his way out. **(b)** `notable` is capped at `RETIREMENT_NOTABLE_LIMIT` (15) and this is a *save-size* cap as much as a DOM cap: the list is persisted per season and thousands of unsigned players now retire per offseason, so an uncapped list is the 88 MB save and the `/transfers` freeze at once. `total`/`rostered` carry the true numbers. The user's own retirees are never dropped (same guarantee `WINDOW_TRANSFER_LIMIT` makes about his own deals), but they still sort by ovr rather than being pinned top. **(c)** The field is **optional and deliberately never backfilled** — a season that ran before the record existed deleted its retirees without a trace, so `migrate.ts` leaves it absent and the page says so rather than inventing a list. Also: no `/player/<pid>` link on those rows, the profile would be empty.
- Audited with `scripts/retirementAudit.ts` (pool size, **min AI roster size** — the real safety metric, since retirement runs immediately before AI free agency draws from the pool — D1 mean ovr, squad age, count still active at 38+). Measured vs an origin/main baseline, same seed, at season 13: free-agent pool 5194-and-still-climbing → **2136 and plateaued** from season 9, players still active at 38+ 24 → **71**, min AI roster 18 → **22**, D1 mean ovr **55.6 → 55.7 (unchanged)**. **The prospect exemption is what holds that last number**: without it D1 mean fell to 52.4, because washing out young FAs starved AI free agency of the useful under-24s it fills holes with, leaving barbell squads of teenagers and veterans. Any future move on `RETIREMENT_UNROSTERED_BASE` or the exemption threshold must re-check D1 mean ovr against a baseline, not just pool size.

**The `/transfers` freeze — root cause (2026-07-25)** — *the actual fix for "the transfers tab freezes and I can't open it".*
- **`WINDOW_TRANSFER_LIMIT` (50, `constants.ts`) caps the "Completed This Window" list**, which was uncapped. A 240-club world moves thousands of players per summer window; a real user save (season **5**, so this is not an aged-save problem) rendered **2056 `<li>` rows, 2066 flag `<img>`s, 10684 DOM elements and ~1 MB of SVG flag art**. After the cap: **603 elements, 60 flags, 17 SVGs**.
- **Why every profiling pass missed it:** the JS render of that page is **147ms** even at 2056 rows. The cost is entirely **layout, image decode and paint** — invisible to Node and to jsdom (neither lays out or paints). Measuring core functions, `renderToStaticMarkup` timings and client mounts all came back fast while the page was unusable. **When a page is slow but every JS measurement is fast, count DOM nodes and image bytes, not milliseconds.**
- **Flag SVGs are the multiplier**: `src/ui/assets/flags/` holds coats of arms up to **240 KB** (`bo`), 217 KB (`ec`), 153 KB (`es`), 143 KB (`mx`) — all rendered at **13px tall** by `<Flag>`. Any surface listing many players pays this. Keep per-page flag counts bounded; `scripts/flagWeightProbe.ts` weighs a list.
- The user's own deals are always shown; the remainder is the biggest-by-fee, with a count and a News Feed link. `test/ui/windowTransferCap.test.tsx` pins the row/element/flag ceilings.
- **`scripts/probeUserSave.ts`** times every Transfers derivation against a real exported save — the tool that finally located this. Point it at a `/leagues` → Export JSON.

**Split player storage — saves write only what changed (`src/db/`, 2026-08-10).** Plan and measurements: `docs/save-performance-plan.md`. **The reframe worth internalising: save *size* was never the real problem — single-record *atomicity* was.** Every prior fix here (the free-agent cull, `archiveCup`, `WINDOW_TRANSFER_LIMIT`, `RETIREE_ARCHIVE_LIMIT`) shrank the save, which only helped because we had made total size the thing touched on every action. BBGM's database is also large at 100 seasons; it stays fast by storing entities as separate records so cost tracks what changed. Shrinking buys a constant factor, splitting changes the exponent.
- **Schema v2** (`database.ts`): a second store, `players`, one record per player keyed **out-of-line as `[lid, pid]`**. The compound key makes a league's pool a single range query (`IDBKeyRange.bound([lid], [lid, []])` — arrays sort after numbers, so `[lid, []]` is an upper bound), so **no index is needed**. `StoredLeague` = `LeagueStore` minus `players`, plus optional `players` (v1 records) and `writeSeq`.
- **`loadLeague` reassembles** the two halves into an ordinary `LeagueStore`, which is why `migrate.ts`, `exportImport.ts`, `src/worker/*` and every reader of `league.players` are **untouched**. Containment is what made this a one-file change.
- **The dirty set is a reference-identity diff**, valid only because the core is purely functional — it maps over players and passes unchanged ones through *by reference* (the sole `players.push` in the repo is a test fixture). **`test/db/playerIdentity.test.ts` is the gate, not a nicety**: if anything ever mutates a player in place, the diff calls it clean and the edit is silently never persisted — no type error, no crash, and nothing else in the suite would notice.
- **The last-written pool lives in the db layer**, keyed by lid, *not* in `LeagueContext` (the plan assumed the latter). No call site can forget it. Cross-tab staleness is caught by **`writeSeq`** on the league record: if disk doesn't match what we last wrote, the save degrades to a full rewrite rather than merging two states that never coexisted. `loadLeague` deliberately does *not* seed the cache — migration rebuilds player objects, so a loaded pool can't be assumed to match disk; first save of a session is therefore full.
- **One transaction over both stores is a correctness requirement**, not tidiness: `teams[].roster` holds pids, so a crash between the two writes leaves rosters pointing at players that don't exist.
- **Migration is lazy, in `loadLeague`, not in `upgrade()`** — testable, and a large save can't stall a versionchange transaction at startup. Interrupted = save left in its old shape, retried next load.
- **The one-way door is wider than it looks, and this was verified rather than assumed.** Once a `DB_VERSION` 2 build opens the database *once*, a version-1 build's `openDB` fails with **`VersionError`** — IDB refuses to open below the stored version. So an older build loses access to **every save in that browser profile, migrated or not**, not just the one that was upgraded. **Deploy rollback is therefore a total outage** for anyone who loaded the new build (no data loss — rolling forward restores it). Matters doubly here: two accounts share this repo, so whoever is on the older branch hits it too. Export JSON is the escape hatch.
- **Measured** (`scripts/savePerfProbe.ts`): single-player actions **1 dirty player, 0.01% of the save**; lineup/scouting/release write **zero** players. 8-season save: routine action **281ms → ~118ms** (3-season: 99 → 35). **Phase 1 alone was a regression** (99 → 335ms writing every row individually) — it must never ship without the dirty set. **Sims are barely helped** (a matchday dirties 8076 of 8076 by identity, 5992 genuinely) and their real cost is the worker `structuredClone`, which this doesn't touch.
- **Two live follow-ups.** (a) The remaining floor is the non-player fields, ~7.8 MB at 8 seasons and **almost all append-only** (`powerRankingHistory` 2.3, `transfers` 1.7, `newsEvents` 1.3, `seasonHistory` 0.7, `cupHistory` 0.6) — splitting those is the next win and is *easier* than this was. (b) **Making `simThrough`'s blanket player copy lazy was measured and rejected**: 26% ceiling on the one action users already accept as a pause, against touching the hot path in a repo with a history of RNG-order accidents. Don't revisit without new numbers.
- **Unverified in a real browser:** the save now reads and writes inside one IDB transaction, and `fake-indexeddb` is more forgiving about transaction auto-commit than Safari. Every await is on a request in that transaction, which should hold, but confirm by playing a save before trusting it.

**Save size & the free-agent cull** (`core/players/freeAgentCull.ts`, 2026-07-25) — *the fix for the "transfers page freezes the whole game" reports; see resolved design decision 6 for the measurements.*
- **Two separate problems shared one symptom. The `/transfers` freeze is fixed by `WINDOW_TRANSFER_LIMIT` (below), NOT by the save-size work here** — that was a real but distinct problem, and attributing the freeze to it was wrong. That page's own *derivations* are flat ~40-100ms even on a 24-season save. The cost is **total save size**: every mutation writes the *whole* league to IndexedDB and every sim `structuredClone`s it to the worker, both on the main thread, both scaling with size. `/dashboard` was nearly as bad. Baseline at 14 seasons: **88 MB, clone 4230ms, save 2756ms** (superlinear; mobile is 5-10× slower, matching production INP p75 31.5s / worst 539s).
- **Two bloat sources, both now fixed.** (1) **`archiveCup`** (`core/cup/archive.ts`) folds a finished cup's box scores into one `CupPlayerLine` per player (`CupState.statLines`) and drops them, at the offseason archive point and in `migrate.ts` — **18 MB of an aged save down to 431 KB across 13 cups (~8×)**. Everything the UI draws is stored separately and survives (scorelines, aggregates, `legs`, winners, the LP table, the bracket); the box scores' only reader was `cupStatsForPlayer`, which now prefers `statLines` and falls back to summing box scores for the *live* cup. Verified on real simmed cups (`scripts/cupBoxScoreCheck.ts`): all three stages → 0 box scores, ~369 stat lines kept, scorelines/winners intact, idempotent. **`CupTie.boxScore` is now `BoxScore | null`** — note **international tournaments reuse `CupTie`**, so `simIntl.ts`/`tournament.ts` needed null guards. Every list read in the archive path is defaulted (`?? []`) because it runs inside `migrate` on every archived cup, where a throw would stop the save loading at all (verified: `cupStatsForPlayer` iterates only `cup.ties`; `Cup.tsx` has no `boxScore` reference, its table comes from `leaguePhaseTable`; `clubHistory` only keys cups by season). (2) `cullFreeAgentPool` deletes unsigned free agents who are `age ≥ FREE_AGENT_CULL_MIN_AGE` (24) **and** career-peak ovr ≤ 65 **and** potential ≤ 65. Result: **88 → 54.7 MB, clone 4230 → 370ms (11×), save 2756 → 736ms**, and the pool plateaus (~5.3k, increments decelerating) instead of growing forever.
- **Aggregating fixed a long-standing cup-stat under-count.** The cup's three stages live in three places (`leaguePhase.matches`, `playoff.ties`, top-level `ties`) and `cupStatsForPlayer` read **only the last**, so league-phase and playoff appearances never reached a profile: a club that played 6 group games and lost the playoff showed **0** cup appearances for every player, and even a quarter-finalist lost his group games. Measured on one real season: **1857 appearances played, 199 counted** (253 of 374 players showed nothing). `aggregateCupStats` now sums all stages, so cup appearances/goals jump for anyone who played group games — that's a correction, not inflation, and it's player-visible (Manual + Changelog both say so). `scripts/cupUndercountDemo.ts` reproduces the old behavior.
- **Retirement already deletes players outright** (offseason step 3), so a save holds **no retired players** — every off-roster player is an unsigned free agent, and nothing ever culled them (9245 unsigned vs 5996 rostered at 14 seasons, 96% never past ovr 55). Don't repeat the mistake of reading that bucket as "retired".
- **The age+potential gates are load-bearing, not caution.** A 17-year-old at ovr 45 with potential 80 has a career *peak* of 45, so culling on peak alone deletes the youth pipeline before the user sees it on `/incoming-talent`. Award winners are protected too (`awardedPids`), so no honours board can point at a deleted player.
- **`LeagueStore.nextPid` is a persisted monotonic pid allocator, and this is a correctness fix, not bookkeeping.** Pids used to be `max(players.pid) + 1` at each use (`offseason.ts`, `godMode.ts`), which silently reuses a pid whenever the highest-pid player is removed — and removal already happened via retirement. The reused pid then inherits that player's transfers/newsEvents/cup lines, since a pid is the only link. Backfilled as `max(pid)+1` so no save changes behavior on upgrade. Both call sites guard a missing cursor (`Number.isFinite`) because `Math.max(undefined, n)` is `NaN`, which would land straight in a player's pid — a test fixture casting `as LeagueStore` hit exactly this.
- **The cull necessarily shifts the RNG stream** (offseason step 2 progresses *every* player in the array with a draw each, so a shorter array = fewer draws = different downstream league). That's inherent to deleting players, not a slip, but it means the pre-cull dynasty baseline no longer applies. `scripts/cullDynastyAudit.ts` re-checks the invariants; **the only trustworthy way to read it is against the same script run on `main`** (copy it into a `git worktree add` of `origin/main`), because several metrics drift on main too. Measured 25 seasons, main → cull: inflation drift **+4.17 → +4.26** (seed 1), **+4.24 → +4.23** (seed 2); AI tier-2 players over the 70 ceiling **579 → 581** (seed 2); champion pts mean **83.8 → 84.1** / **85.3 → 87.0**; worst AI budget **+7.9M → −0.8M** (seed 1) but **+10.6M → +11.1M** (seed 2), so that lone small deficit is stream-shift noise, not a systematic effect. Free agents at season 25: **13961 (still climbing) → 5689 (plateaued)**; prospects **6157 → 5534**, so the pipeline is intact.
- **Two pre-existing findings this audit surfaced, neither caused by the cull** (both identical on main, both left alone): league-wide mean ovr drifts **~+4 over 25 seasons**, and `enforceDivision2Ceiling` leaks **~23 over-threshold AI tier-2 players per season**. If either matters, they're separate work.
- **Exclude `userTid` from D2-ceiling metrics**: a relegated user squad keeps 70+ players in tier 2 by design (`enforceDivision2Ceiling` never sweeps it), which otherwise reads as a breach every single season. Comparing the best D2 player against the tier-1 *full-roster* mean (~57) is likewise a miscalibrated check — it "fails" on main too.
- **`awardedPids` protects honours-board pids, and getting this wrong is silent.** `SeasonAwards` stores **bare numbers** under `playerOfSeasonPid` / `goldenBootPid` / `teamOfSeason[]` — there is no `pid` key — so an earlier version that walked for objects with a `pid` property returned an **empty set for every save**, i.e. the protection did nothing and nothing failed. It now matches `*Pid` keys plus `teamOfSeason`, tolerates all three historical award container shapes (single / `[D1,D2]` tuple / `Record<compId,…>`), and covers `international.history[].topScorer.pid` (its `name` fallback saves the label but the profile *link* still uses the pid). Reachable, not theoretical: tier-2 squads are capped below `DIVISION_2_REFUSAL_OVR_THRESHOLD`, so a second-division Golden Boot / Team-of-the-Season pick can sit at peak ovr ≤ 65. **`scripts/freeAgentPoolAudit.ts` shared the same bug**, which is why it reported zero award references — don't read that as evidence.
- **The load-time cull is gated on pool size** (`cullOnLoad`, `FREE_AGENT_CULL_LOAD_THRESHOLD` 7000). Culling on *every* load makes mid-season deletion immediate — release a player by mistake, reload, and he's gone instead of re-signable from `/free-agents`. Only a genuinely bloated pool (the frozen-save case, 9245 in the save that prompted this; a maintained pool plateaus ~5.3k) is drained at load; everything else waits for the offseason cull.
- **`loadLeague` writes the shrunk record back** when migration removed players or collapsed a cup. Without it the on-disk save stays full size and every startup re-reads it and re-runs `aggregateCupStats` over every archived cup before first paint — the exact main-thread cost this set out to remove. The check is deliberately cheap (player count + `statLines` identity), since serializing twice to compare sizes is itself the cost being avoided.
- **There are THREE pid allocators, all now on the cursor:** `offseason.ts` (youth intake), `godMode.ts` (`createCustomPlayer`), and **`rosterImport.ts` (`applyRosterFile`)** — the last one was missed initially. It matters most there because **retirement deletes players without scrubbing** their transfers/newsEvents/cup lines, so a reissued pid inherits real history.
- Dangling references are scrubbed with the player (transfers, newsEvents, negotiations, inboundOffers, loan listings/rejections, `scoutingObserved`, **every cup stage's box-score lines and the archived `statLines`** — `scrubCupLines` covers `leaguePhase`/`playoff`/`playIn`/`ties`, not just `ties`, because `cupStatsForPlayer` reads them all, **and the live international campaign's `NationSquad.pids` + `stageInjuries`** — squad selection reads end-of-season club rosters and a weak nation can genuinely name a sub-65 player, so a culled player really can be sitting in one; archived campaigns already discard squads, and `IntlTournamentSummary.topScorer` carries a `name` fallback, so neither needs it) — not a crash if left (every reader guards the lookup) but it renders as "Player 4821" in history.

**God Mode** (`core/godMode.ts`) — per-save sandbox (`LeagueStore.godMode`). Guardrail-free editing (bypasses fees/budget/cap/depth-floor): move/release/edit/create players, set club finances; un-fogs potential everywhere. `detachPlayer` scrubs a pid from all rosters + transient state. `PlayerEditModal.tsx`, `/god-mode` hub. Scope-outs: no add/delete clubs, no hard-delete (release instead), no forcing match results.

## Open design decisions (need a user call before coding)

From the 2026-07-11 bug hunt; each has more than one reasonable fix — discuss options first:
1. **Winter-sale wage dodge** — season wages charged once at offseason settlement against the current holder, so selling a high earner in winter dodges his whole season bill. Pro-rate, charge-at-transfer, or accept+document.
2. **Deficit at the 30-man cap** — the "no club runs a deficit" tuning was only proven for the 25-man composition; a stacked full user squad with a low finish can go negative. Retune, cap scouting relative to wages, or allow user deficits + add debt UI.
4. **Mid-season transfer stat attribution** — `SeasonStats` is one running total; Leaders/Roster credit the whole line to the *current* club. Per-stint stats (schema change) or a "joined mid-season" UI marker.
6. ~~**Unbounded save size**~~ — **RESOLVED 2026-07-25, see "Save size & the free-agent cull" below.** ⚠️ Note the framing here is *wrong*: this was diagnosed as the cause of the `/transfers` freeze, and it is not. The freeze is an uncapped DOM list (see "The `/transfers` freeze — root cause"). Save size was a genuine, separate problem. Original measurement kept here because it's the reference baseline: **Unbounded save size — the real cause of the "transfers page freezes" reports (measured 2026-07-25).** The save grows without bound and **every mutation writes the whole object to IndexedDB** while **every sim `structuredClone`s it to the worker** — both block the main thread, both scale with total size, so the whole app freezes and it gets worse the longer you play. Measured on a fast desktop (`scripts/leagueSizeTiming.ts`): season 1 → 9 MB / clone 67ms / save 75ms; season 9 → 59 MB / 716ms / 542ms; season 14 → **88 MB / clone 4230ms / save 2756ms**, growing superlinearly. Mobile is 5-10× slower, matching production INP on `/transfers` (p50 6.3s, p75 **31.5s**, worst 539s) — and `/dashboard` is nearly as bad, because **it is not a transfers-specific bug at all**. Per-field at 14 seasons (`scripts/leagueSizeBreakdown.ts`, `scripts/leagueSizeDeepDive.ts`): `players` 56.2 MB (64%; `hist[]` **34.0 MB** / 127k rows, `stats[]` 16.0 MB), `cupHistory` **18.6 MB** (21%), `transfers` 5.2 MB, `powerRankingHistory` 4.0 MB, `newsEvents` 2.4 MB. Candidate savings: drop every off-roster player 24.7 MB (28%) · **strip `boxScore` from archived cups' `leaguePhase` matches 14.8 MB (17%)** · drop `hist[]` for off-roster players 17.5 MB (20%) · `powerRankingHistory` 4.0 MB · off-roster `stats[]` 3.3 MB. **The league-phase one is free of feature cost — verified nothing reads it:** `cupStatsForPlayer` (`core/cup/cupStats.ts`, the Player Profile Cup tab) iterates only `cup.ties`; `Cup.tsx` has no `boxScore` reference and builds the table via `leaguePhaseTable` from scores; `clubHistory.ts` only keys `cupHistory` by season. Everything else trades away real history (retired players' OVR chart / career stats), hence a user call. Any fix needs a `migrate.ts` change and **deletes data from existing saves**, so confirm before shipping.
